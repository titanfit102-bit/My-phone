# SECURITY_TEST_MATRIX — My Phone Expo Studio

**Test matrix e vetme** për kontrollin proporcional të rrezikut. Gjendjet aktuale dhe vendimi i release-it ruhen **vetëm** në [SECURITY_REGISTER](SECURITY_REGISTER.md), jo në këtë tabelë. Kodi referencë: [Draft PR28](https://github.com/titanfit102-bit/My-phone/pull/28) `65e989680e9c6ccec2495b46c62342c483c6c389`. Testet që ekzistojnë sot përdorin `studio/package.json` dhe [workflow standard](../../.github/workflows/studio-verify.yml).

## 1. Kontroll proporcional, pa duplikime

## 3. Propozime për mbulimin e mbetur CI (mbi skanerin ekzistues Draft PR30)

**Statusi i implementimit:** [PR30](https://github.com/titanfit102-bit/My-phone/pull/30) tashmë ofron kontroll minimal falas për secrets/sinks/CSP me teste reale në Draft, por **jo në main**. Pikat më poshtë janë ide të pambuluara ose kërkesa për integrim/admin, jo kontroll aktiv.



**Ekzistueset nuk i dyfishojmë.** Shto vetëm në një Draft PR të veçantë dhe pas miratimit të scope-it, duke mos prekur fail-closed dependency policy:
1. **Mbulimi i mbetur për secrets:** PR30 skanon të gjitha Git-tracked files për modele të sigurta GitHub/AWS/Slack/PEM/URL; përpara implementimit shtesë vlerëso high-entropy/diff-aware detection dhe formatet Vercel, pa dërgim kodi në shërbim të jashtëm. Për të ulur false-positive, rregulla testi dhe listë të kufizuar për fixture *fiktive*; çdo përjashtim kërkon review. Mos publiko vlerën që gjendet në log.
2. **Mbulimi i mbetur JS/TS taint/SAST:** PR30 bllokon `dangerouslySetInnerHTML`, `eval`/`Function` dhe dobësim të invariantit Quick Preview/CSP; ende pa analiza të rrjedhës secret→preview, rrugë ZIP traversal/decompression dhe kontrolle dinamike. Prefero rules të auditueshme dhe regression fixtures pozitive/negative, jo opinion vetëm nga grep. Raporto scanner coverage dhe version.
3. **Trigger/gate:** në PR drejt main dhe branch-et aktive të miratuara; run `security-static` vetëm për `studio/**`, `scripts/**`, workflow/dependency changes; mos përdor të njëjtin scanner dy herë në push+PR. Për release, audit + static + full existing workflow **required** sipas policy admin. Degradimi i security scanner duhet të jetë bllokues, jo `continue-on-error`.
4. **A04 PoF**: prova e fail-closed/positive-controls të futet në workflow-in e repo-së së veçantë vetëm pas autorizimit të shprehur, jo në këtë Draft My-phone.

**Propozim branch protection (vetëm për përdoruesin/adminin):** ndalo direct/force push në `main`, kërko 1 review, `Verify Expo Studio / expo-web` dhe një check statik unik pas implementimit, status green në SHA merge-commit, mos lejo bypass në deployment. Siç është tani, `main` protection **nuk mund të lexohej** (403); asgjë nuk u aktivizua.

## 4. Protokoll verifikimi dhe raportimi

- Kontrollo branch HEAD + PR base + `git compare` kundër SHA të testuar; në proof-branch sigurohu që **vetëm workflow i provës** është ndryshuar nëse thua `code-identical`.
- Ruaj referencën e run-it, `node/npm/Expo` versionet kur relevant, numër PASS/FAIL/SKIP, testet negative, SHA e kodit dhe statusin **IMPLEMENTED / VERIFIED / PUBLISHED** veçmas.
- **FAIL i security gate** ose required check i papërfunduar e bllokon release edhe nëse testet funksionale janë të gjitha PASS. Review afatit të përjashtimeve ekzistuese: **2026-11-21**. Nuk përdoren shërbime me pagesë pa miratim.
- Kur evidenca skadon/ndryshon, mos ruaj një PASS historik si certifikim aktual; riekzekuto vetëm testet që varen nga ndryshimi dhe release gate kur duhet.
